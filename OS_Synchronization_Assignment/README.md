# Operating Systems Synchronization Assignment

## Contents
- `readers_writers/semaphore_solution.py` — semaphore-based Readers-Writers.
- `readers_writers/monitor_solution.py` — monitor-style Readers-Writers using `threading.Condition`.
- `dining_philosophers/semaphore_solution.py` — four philosophers, semaphore-based deadlock prevention.
- `dining_philosophers/monitor_solution.py` — four philosophers, condition-variable monitor.
- `generated_html/` — the four HTML files generated by running the source programs.

## Requirements
Python 3.10+; standard library only. No pip installation required.

## Run (Windows PowerShell or terminal)
From the project root, run each command separately:
```bash
python readers_writers/semaphore_solution.py
python readers_writers/monitor_solution.py
python dining_philosophers/semaphore_solution.py
python dining_philosophers/monitor_solution.py
```
Each command runs real threads, captures state/event data, and writes its corresponding HTML file into `generated_html/`. Open the resulting HTML files in a browser. Dining Philosophers pages include animated replay, speed, step, reset, and timeline controls.

## Design notes
- Semaphore Readers-Writers uses a binary semaphore for the reader count and a binary resource semaphore. It is a reader-preference design; a continuous stream of readers can starve a writer.
- Monitor Readers-Writers uses a condition variable to guard active-reader count and writer state. Waiting writers are preferred over new readers.
- Semaphore Dining Philosophers uses `room = Semaphore(3)` and four fork semaphores. Restricting contenders to three prevents all four philosophers from holding one fork while waiting for another. Semaphore fairness/starvation is not guaranteed.
- Monitor Dining Philosophers checks both neighbors under a condition lock before granting the two forks. This prevents adjacent philosophers from eating at once. A fairness queue would be needed to guarantee starvation freedom.
